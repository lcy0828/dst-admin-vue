# DST Admin 功能真值

更新时间：2026-08-16。本文记录正式前端 `master` 与后端 `feature/v2-rebuild` 的真实能力，不把设计稿、占位页面或未来计划算作已完成。

## 状态定义

- **可用**：已有真实接口和用户入口，并通过自动测试、构建或本机真实 DST 环境验证。
- **部分可用**：主流程存在，但平台、远程节点、自动化验收或次要动作仍有明确边界。
- **未实现**：没有可交付的真实流程；即使仓库存在旧文件或占位页面，也不计为可用。

## 当前发布基线

| 范围 | 状态 | 事实 |
| --- | --- | --- |
| 前端技术栈 | 可用 | Vue 3.5、Vue Router 4、shadcn-vue/Reka UI、Tailwind CSS 4 |
| 正式界面 | 可用 | `/dashboard` 及全部正式业务路由使用 shadcn 布局；`/preview-v2/*` 仅作兼容重定向 |
| 数据来源 | 可用 | 业务页面读取真实后端接口，不使用演示或随机数据替代失败响应 |
| 默认运行目标 | 可用 | 控制面默认管理本机；远程 Agent 在 Agent 页面单独配置，在运行拓扑中按世界分片选择，不再切换整套应用上下文 |
| 自动质量门禁 | 部分可用 | 前端 lint、Node 测试和生产构建已接入；尚无浏览器 E2E |

## Mod 兼容结论

Mod 读取顺序固定为：内嵌 gopher-lua、外部 Lua、Python/Lupa。保留 Lua fallback 是为了兼容使用复杂 Lua 行为的 Mod；Go 主路径失败时不能伪造空配置或静默丢字段。

在 `192.168.2.12` 的 46 个已安装 Workshop Mod 样本中，Go 主解析和新内嵌 fallback helper 都达到 46/46。该结果是当前样本证据，不等于对未来所有未知 Mod 的数学保证。

## 仍未完成

1. 可证明同一保存点的 `hot-consistent` 跨分片保存屏障；当前只提供会停服的 `cold-consistent`。
2. Kubernetes 生产 Driver；当前只有默认关闭的 status/observe/preflight，只读且 `applyAllowed=false`。
3. 远程分片通用房间/世界配置文件的原子分发，以及直接在远程目录发现或创建房间。
4. 浏览器级真实流程 E2E，以及对应的发布自动化。
5. 两步验证（2FA）。
6. `cluster.ini` 独立导入/导出工作流。
7. 旧物品目录和生成器占位文件的真实 API 接入与正式路由。
8. Podman、macOS 容器和完整 Linux 真实 DST 故障注入矩阵。

## 发布前人工验收

在浏览器 E2E 接入前，发布必须使用真实后端手工完成：登录、正式侧栏导航、创建房间、Master/Caves 启停、失败重试、运行拓扑与迁移、Mod 搜索/配置/发布、玩家动作、普通与分布式备份恢复、日志 SSE、集中诊断、结构化日志解析与检索、Lua 控制台确认和移动端关键页面检查。

任何“暂无数据”都必须能和“加载失败”“功能未开放”区分；任何未实现的远程文件动作都必须被阻止，不能调用控制面同名本机路径作为 fallback。
